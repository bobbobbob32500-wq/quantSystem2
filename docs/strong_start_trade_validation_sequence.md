# strong_start 交易版验证顺序（严格流程）

## 阶段 A：交易信号定义验证（优先）
- 目标：
  - 把研究版输出转换为交易候选信号定义
  - 固定候选分层口径
- 输入：
  - `strong_start_research_v4_freeze1` 输出字段
  - 输出契约与错位风险清单
- 输出：
  - 交易候选定义文档
  - 分型（breakout/pullback）信号草图
- 验收标准：
  - 每个事件可唯一判定候选层级
  - 不引入未来字段
- 当前是否允许开始：**允许（当前阶段）**

## 阶段 B：执行假设验证（仅规范，不跑绩效）
- 目标：
  - 冻结执行时点与成交假设
- 输入：
  - 阶段A信号定义
- 输出：
  - 执行口径规范（T+1开盘/盘中触发/回踩确认）
  - 可成交与不可成交规则
- 验收标准：
  - 各执行口径边界清晰且可审计
- 当前是否允许开始：设计允许，执行验证不允许

## 阶段 C：出场与风控规则验证设计
- 目标：
  - 冻结退出与风控草图，形成可验证规则集
- 输入：
  - 阶段A/B文档
- 输出：
  - 出场规则规范（结构/时间/动量/板块退潮）
  - 分型风控方案（breakout vs pullback）
- 验收标准：
  - 每条规则可事件化，不依赖事后解释
- 当前是否允许开始：设计允许，绩效比较不允许

## 阶段 D：交易版回测规范设计
- 目标：
  - 在回测前冻结事件流与防前视机制
- 输入：
  - 阶段A/B/C规则规范
- 输出：
  - 回测事件流规范
  - 数据对齐规范
  - 禁止项清单
- 验收标准：
  - 能明确识别并规避时点错位与未来函数风险
- 当前是否允许开始：设计允许，回测执行不允许

## 顺序约束（必须遵守）
- 不得跳过 A/B/C 直接进入回测。
- 每阶段验收通过后才可进入下一阶段。
- 任何规则调整必须版本化，不能覆盖 freeze1。
