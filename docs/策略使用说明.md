本文面向**实盘 / 仿真盘运维与复盘**，分两部分：**（一）主板二次启动**、**（二）突破策略与宽进突破**。说明各策略在本项目中的**正确用法、配置入口、回测工具与风险边界**。数值以历史回测为参考，**不保证未来收益**。

## 文档索引（重要）

- `Alpha158` 最新执行建议、实测指标与风控阈值，请优先查看：`docs/策略使用文档.md`。
- 本文仍作为多策略总览与背景说明文档保留。

**执行建议（按优先级分配）**：
- 主策略：`P1`（突破）  
- 次主策略：`P2`（宽进突破）  
- 补充策略：`P3`（Alpha158，建议在趋势市优先启用）  
- 观察/择时策略：`P4`（二次启动，建议配合分钟确认与更严格风控）

**说明**：不同策略的持有期与统计口径并非完全一致，优先级用于日常调度与仓位分层；每月应基于最新滚动样本外结果复核一次。

# 第一部分：二次启动策略

## 一、策略定位（适合什么人用）

- **风格**：主板短线偏进攻，强调「涨停基因 + 缩量回踩 + 二次启动形态」，在**分时上再确认**后才视为可买。
- **适用**：能接受**中频交易**、有**分钟数据**与**盘后复盘**习惯；对**单段样本外回撤**有心理与资金准备的用户。
- **不适用**：无分钟数据源、无法盯盘或无法执行推送纪律；或期望「日线一键满仓、长期躺赢」的资金属性。

---

## 二、运作机制（务必统一理解）

1. **T 日盘前选股（逻辑上）**  
   选股所依据的日线特征，来自 **T−1 及更早已收盘数据**（不在盘中偷用 T 日未收盘日线）。  
   信号落在 **T 日**（代码与报表中的 `signal_date` / 交易日）。

2. **T 日盘中买入**  
   买点由 `detect_secondary_launch_signal` 在 **T 日分钟序列**上递增回放判定；**首次触发**的分钟收盘价，在回测里记为**买入价**。  
   监控窗口：**9:35～14:20**（窗口外不判二次启动买点）。

3. **分层执行（与选股档次对齐）**  
   盘中在「回踩 / 平台突破」双通道上，结合 **A 直通 / A 弱确认 / B 强确认** 与行业、大盘闸门放行；推送与复盘应携带**档次与触发类型**，避免与冷却逻辑冲突。

4. **「T+1」在收益报表里的含义**  
   回测表中的 **T+1 收盘**，指 **买入日 T 的下一交易日** 收盘相对**触发买入价**的收益；**不是**把「买入日」叫作 T+1。  
   A 股「T+1 可卖出」制度另指**卖出限制**，勿与报表标签混用。

---

## 三、配置入口（单一真源）

主配置：`src/config/config.yaml` → `stock_selection.secondary_launch`。

建议重点核对（版本变更时逐项对照）：

| 类别 | 配置项含义（简述） |
|------|-------------------|
| 持仓 | `hold_days`：日线机械回测持有天数；与分钟「何时卖」不是同一套逻辑。 |
| 分层阈值 | `direct_score_min`、`direct_lgb_min`、`semi_score_min`、`semi_lgb_min`、`direct_conf_min`、`semi_conf_min`：与盘中分层、选股层 `execution_tier_hint` 口径对齐。 |
| 震荡市限流 | `sideways_market_ret5_low/high`、`sideways_market_min_score_boost`、`sideways_market_max_picks`：当前激进方案为 **震荡区间抬高最低分 + 当日 `max_picks=0` 暂停开新仓**（以样本外对比报告为准调参）。 |
| 弱市 | `weak_market_ret5_threshold`、`weak_market_min_score_boost`、`weak_market_max_picks`。 |
| V4 选股 | `risk_penalty_weight`、上影线/放量/深跌等惩罚项：用于**边缘票降权**，需定期做分组归因再调。 |

**原则**：盘中候选、日报复盘、菜单回放，应使用**同一套阈值**（从配置读取或显式注入 `candidate`），避免「回测一套、实盘一套」。

## 四、日常使用流程（推荐顺序）

1. **盘前**  
   - 用二次启动菜单或流水线生成 **T 日候选**（排名、分数、`execution_tier_hint` 等）。  
   - 确认候选已写入融合监控所需的数据源（如 `candidate_pool.json` 与库表，以你当前部署为准）。

2. **盘中**  
   - 开启融合监控；关注**分钟是否缺失降级**（缺失时置信度可能被压低，信号可信度下降）。  
   - 同档同类型推送有冷却；**档次或触发类型变化**时可更快提醒，但仍受最短间隔保护。

3. **盘后**  
   - 用日报/复盘脚本核对：**选股有、买点无**时，是「未触发」还是「分钟缺失」。  
   - 对连续亏损段，优先看 **市场状态（牛/震/弱）× 档次** 分组，再决定调闸门还是调阈值，避免在全样本上盲目网格寻优。

以下脚本均依赖 `data/database/quant_system.db` 与 `data/history_recommendation.db`（路径以配置为准）：

## 六、交易频率（参考值，非承诺）

以最近一次扩展回测（约 **20251011～20260414**）为例（见 `data/reports/secondary_launch_halfyear_selection_entry_20260415_122905.md`）：

- 选股信号约 **124** 条，有信号日约 **72** 天；分钟触发并记成交约 **75** 笔；**触发率约 60%**。  
- 折算约 **20 条信号/月**、**12 笔成交/月**（按自然日跨度折算，随区间与分钟库完整度变化）。

**解读**：属于**中频**；若触发率异常下降，优先查分钟覆盖与大盘/行业闸门，而不是先放宽买点。

## 七、风险与纪律（必读）

1. **样本外漂移**  
   日线回测在部分区间可能出现 **OOS 明显弱于 IS**；分钟组合收益也会随市场状态变化。**任何单次寻优的「最优」都有时效**，需滚动复盘。

2. **过拟合**  
   分层阈值全量寻优曾出现**边际改善很小**的结论——不要指望靠微调阈值暴利；更应做 **分组归因 + 闸门减法**。

3. **滑点与成交**  
   回测默认用分钟收盘触发价与日线收盘/ T+N 收盘，**未完全模拟**涨停买不进、跌停卖不出、拆单冲击成本。

4. **震荡市激进限流**  
   `sideways_market_max_picks: 0` 会显著减少震荡段出手，**降低回撤与无效交易**，但也可能错过震荡中的少数机会；是否保留应由**滚动对比表**决定，而非一次结论定终身。

5. **纪律**  
   信号只是决策支持；**仓位、止损、合规**仍需单独的风控模块与人工确认。

---

## 八、简要结论（使用建议清单）

- **先保证数据**：分钟与日线覆盖不足的标的，不要强行解读信号。  
- **先统一口径**：配置、候选、复盘、监控共用同一套分层与震荡参数。  
- **先防大亏**：震荡/弱市以「少做、做精」为主，再用小样本验证是否放宽。  
- **定期复盘**：固定区间跑 `halfyear_selection_to_entry` + OOS 报告，看触发率、缺数原因、分组收益。  
- **理性预期**：策略提供的是**概率优势与风险暴露结构**，不是稳赚曲线。

# 第二部分：突破策略与宽进突破

本部分说明「选强→等突破」两条分支：**标准突破**（由配置 `params_preset` 决定，当前仓库常见为 `win_rate_priority`）与**宽进突破**（固定预设 `wide_pool_strict_entry_v2`，菜单独立入口）。日线回测口径为：**T 日盘后选股 → 仅当 T+1 突破且量能确认后以触发价买入 → 统计 T+N 收盘相对触发价的收益率（毛收益，未扣费）**。

## 一、两者差异（选型前先弄清）

| 维度 | 标准突破（如 `win_rate_priority`） | 宽进突破（`wide_pool_strict_entry_v2`） |
|------|-----------------------------------|----------------------------------------|
| 选股层 | 与 `baseline` 同档（池相对窄，如 RS 分位、TopK 等） | 同「放宽选股」`selection_relaxed_v1`（池更大、候选更多） |
| 买点层 | 在 baseline 选股上**收紧**缓冲、量比、日内涨幅等 | 同 **`buy_tuning_v1`**（买点比 `win_rate_priority` 再严一档） |
| 典型表现倾向 | 成交笔数较少，单笔胜率与盈亏比（PF）往往更高，组合回撤相对可控 | 成交笔数更多；单笔均值可能略高，但波动与**组合最大回撤**往往更大；等权日复利累计易受「笔数多」放大，**不等于可满仓复制** |

**结论先行**：没有绝对优劣——**偏质量与回撤控制**优先看标准突破；**偏观察池覆盖面与机会数量**、且能接受更严买点过滤与更大净值波动时，再并行跟踪宽进突破。

## 二、同窗口对比结论（摘要，仅供复盘参考）

在约 **126 个交易日**、与统一对比脚本相同信号窗口的日线回测中（示例区间约 **2025-09-22～2026-04-03**，随数据库最新交易日平移），曾出现如下**相对关系**（具体数值以你本机最新报表为准）：

- **成交笔数**：宽进（约百余笔级）明显高于标准突破（约数十笔级）——因选股池更宽。  
- **单笔 T+3/T+5**：标准突破的**胜率与 PF** 往往更好；宽进单笔**均值**有时略高但**标准差更大**。  
- **等权按信号日复利**：宽进组合累计可能更高，但 **T+3 最大回撤**往往更深；标准突破的**日夏普（年化近似）**往往更占优。

以上均为**历史样本**，市场状态一变，排序可能反转；务必做**滚动窗口与样本外**对照，勿单次定终身。

## 三、使用建议（实操）

1. **不要二选一混用同一套仓位**  
   两条线对应**不同候选池**（如 `breakout` vs `wide_breakout`）：监控、推送、复盘应**打标签区分**，避免同一标的重复计数、重复下单。

2. **资金与性格匹配**  
   - 更在意**少而精、控回撤**：以标准突破为主池，宽进仅作**补充观察**或降权参与。  
   - 更需要**广度与备选名单**（Industry/板块轮动快）：可主用宽进观察池，但应**收紧实盘仓位/单票上限**，因回测回撤更大。

3. **与分时监控对齐**  
   宽进在本地实现中与 **`buy_tuning_v1` 档**对齐；分时突破分支在 `OptimizedBuySignals` 中可使用更严参数组（`breakout_wide`）。实盘应保证**策略画像**（`strategy_profile`）与菜单选股一致，避免「日线宽进、分时仍走默认突破参数」的口径漂移。

4. **成本与滑点心理预期**  
   报表为**触发价毛收益**；实盘需自行扣除**双边成本与滑点**后再评估；笔数多的策略，成本拖累更明显。

5. **定期复跑固定脚本**  
   用同一 `trading_days` 或同一日历区间对比两条线，把**笔数、T+3 胜率/均值/PF、组合回撤、夏普**记入内部台账，观察是否漂移。

## 六、风险与纪律（突破类必读）

1. **过拟合**：宽进「组合累计高」可能来自**笔数×复利**，换一段行情未必成立。  
2. **假突破**：买点已含确认与量能过滤，仍无法消除趋势末端假突破；需结合**大盘与板块闸门**（代码内 `market_gate` 等逻辑）。  
3. **等权组合≠实盘**：报表按信号日等权平均，不是资金容量与成交可行性模拟。  
4. **纪律**：突破类偏进攻，**止损与仓位**须单独约定，信号仅辅助。

## 七、简要清单（突破 / 宽进）

- **先定主辅**：明确主做标准突破还是宽进，另一条作观察或降权。  
- **先统一画像**：选股预设、`strategy_profile`、分时参数三者一致。  
- **先看回撤与 PF**：不要只看单笔均值或组合累计。  
- **定期同窗对比**：跑 `compare_breakout_vs_wide_same_window.py` 更新台账。  
- **理性预期**：突破类吃的是**趋势延续段的统计优势**，不是每日必赚。
