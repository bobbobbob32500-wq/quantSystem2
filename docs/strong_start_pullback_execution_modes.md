# strong_start pullback_candidate 执行口径草图（设计稿）

信号前提：仅对 `trade_signal_class=pullback_candidate` 的对象定义执行口径。  
定位：`pullback_candidate` 当前属于“待执行验证通道”，不是直接交易就绪信号。

## 1) 为什么 pullback_candidate 不能直接等于交易就绪
- 它本质是“结构与触发部分成立，但 breakout 就绪条件未完全闭环”；
- 执行层需要额外确认（承接或结构回踩）才能判断可执行性；
- 若直接就绪，容易把“研究强但时点模糊”的样本误判为交易信号。

## 2) pullback 最需要补的执行确认
- 承接确认：T+1 开盘后是否存在可持续承接；
- 结构确认：回踩是否不破关键结构（不把结构信号打坏）；
- 两者至少明确其一，才具备执行验证意义。

## 3) 与 breakout 的先后顺序
- pullback 通道建议晚于 breakout 通道进入执行细化；
- 原因：breakout 通道定义更清晰，先验证可降低通道耦合风险。

## 4) 两种 pullback 执行口径候选

### 口径 P1：T+1 开盘承接型
- 先决条件：pullback_candidate 成立；
- 执行草图：T+1 开盘后满足最小承接标准再进入执行判断；
- 风险：承接定义过松会放入噪音，过紧会样本骤减。

### 口径 P2：T+1/T+2 结构回踩确认型
- 先决条件：pullback_candidate 成立；
- 执行草图：回踩不破结构，再进入执行判断；
- 风险：确认窗口拖长带来机会损失与定义复杂度提升。

## 5) 当前阶段结论
- pullback_candidate 应保持“执行待验证对象”身份；
- 暂不升级为交易就绪信号；
- 先冻结口径，再进入后续执行可达性验证设计。
