# AI功能本地最终版本开发与验证总方案

## 1. 目标与范围
- 目标：在重大升级后完成 AI 功能本地最终版本确认，确保可用、稳定、安全、可运维。
- 范围：`src/services/ai_service.py`、`src/services/ai_butler_service.py`、`src/api/app.py`、Web/Android 的 AI 交互链路与配置项。
- 交付：版本说明、测试报告、部署指南、问题闭环记录。

## 2. 五阶段执行与门禁
### 阶段A：需求梳理与确认
- 任务：
1. 明确 AI 应用场景：问答、选股解释、信号分析、盘前/盘中/盘后管家。
2. 明确性能指标：API 可用性、延迟阈值、错误率阈值。
3. 明确体验要求：接口兼容、失败可降级、提示可理解。
- 门禁：
1. 需求基线文档已签署（见 `requirements_baseline.md`）。
2. 指标可测量且已映射到自动化检查。

### 阶段B：开发完善与集成优化
- 任务：
1. 统一 AI 接口契约，补充兼容路由（snake_case 与 kebab-case 并存）。
2. 完成系统功能联调，修复已知问题并固化配置基线。
3. 保持 `config/ai_config.yaml` 的本地安全默认值。
- 门禁：
1. 核心 smoke 测试通过。
2. 关键接口兼容策略落地并有测试覆盖。

### 阶段C：多维度验证
- 维度：
1. 功能测试：AI/Butler 核心接口可用，Android-Backend 契约不回归。
2. 性能测试：本地 `/api/ai/status` p95 延迟满足阈值。
3. 安全测试：静态 API key 不落盘、危险动作开关默认关闭。
4. 体验测试：关键 API 兼容别名与交互连续性可用。
- 门禁：
1. `tools/run_ai_local_final_validation.py` 输出总体通过。

### 阶段D：问题修复与优化
- 任务：
1. 对验证失败项进行分级（P0/P1/P2）。
2. 修复后回归验证，记录修复证据与影响面。
3. 至少完成 1 轮“修复-回归-复核”闭环。
- 门禁：
1. 阻塞问题（P0/P1）归零。
2. 回归报告中无新增高风险问题。

### 阶段E：最终版本确认
- 任务：
1. 输出版本说明、测试报告、部署指南。
2. 形成上线检查结论与回滚策略。
- 门禁：
1. 三份文档齐全并可执行。
2. 本地最终版验收结论为“可上线”。

## 3. 一键执行入口
- 命令：`python tools/run_ai_local_final_validation.py`
- 配置：`config/ai_local_final_validation.yaml`
- 报告输出：`reports/release/ai_local_final_validation_*.md|json`

## 4. 角色建议
- 产品/业务：确认场景与体验验收标准。
- 开发：完成接口与集成修复，执行回归。
- 测试：维护验证配置、报告与缺陷闭环。
- 发布负责人：归档最终交付物并签署上线结论。
