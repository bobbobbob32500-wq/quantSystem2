# strong_start 不可执行 / 执行存疑边界（设计版）

用途：把“研究强”与“可执行”明确分开，降低研究信号误用风险。

## 1) 高开脱离型（不可直接执行）
- 特征：T+1 开盘即明显偏离合理执行带。
- 风险：研究信号仍强，但执行成本与风险结构已改变。
- 处理：标记 `execution_risk_tag=gap_risk_high`，进入存疑通道。

## 2) 一字或近一字无法合理参与型（不可执行）
- 特征：流动性与价格行为使得合理参与不可达。
- 风险：研究信号“看对”但交易不可实现。
- 处理：标记 `execution_reject_reason=unreachable_liquidity_or_limit_state`。

## 3) gap 过大型（执行存疑）
- 特征：T+1 跳空幅度过大，突破逻辑与执行价格脱节。
- 风险：把结构信号强行映射成高风险追价。
- 处理：进入待验证通道，不直接执行。

## 4) 盘中确认依赖过强、日线无法安全映射型（执行存疑）
- 特征：必须依赖分时细节才能确认，而当前仅日线口径。
- 风险：日线条件满足不代表盘中执行可行。
- 处理：标记 `execution_risk_tag=intraday_confirmation_required`。

## 5) breakout 与 pullback 结构模糊型（执行存疑）
- 特征：分类边界不清，执行策略不明确。
- 风险：通道混用导致执行规则失真。
- 处理：保留为 `watchlist` 或 `pullback_candidate` 待验证对象。

## 6) 解释强但触发不完整型（不可直接执行）
- 特征：评分高、解释好，但触发闭环未完成。
- 风险：典型“研究强 -> 交易假强”。
- 处理：不得升级为 `trade_signal_ready`。

## 边界使用原则
- 这些边界是执行验证规范的一部分，不是临时注释。
- 任何命中边界的样本必须有结构化拒绝原因输出。
