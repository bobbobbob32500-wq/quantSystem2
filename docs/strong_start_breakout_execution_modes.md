# strong_start breakout 执行口径草图（设计稿）

信号前提：仅对 `trade_signal_class=breakout` 的候选定义执行口径。  
注意：本文件仅定义口径，不做执行结果评价。

## 执行口径 A：T+1 开盘执行

### 定义
- T 日收盘后 breakout 信号成立；
- T+1 开盘按预设规则进入执行判断。

### 适用对象
- 高置信 breakout（`high_confidence`）；
- 触发链路完整且解释稳定的候选。

### 优点
- 口径清晰、规则简单、事件流容易审计。

### 风险
- 高开脱离导致追价偏离；
- 无法区分“开盘强延续”与“高开回落”。

### 典型错位
- 研究上 breakout 强，交易上 T+1 开盘可达性差。

---

## 执行口径 B：T+1 盘中继续确认后执行

### 定义
- T 日收盘确认 breakout 候选；
- T+1 仅在盘中满足“继续确认”条件后进入执行判断。

### “继续确认”草图
- 价格不跌回关键结构位下方；
- 量价延续满足最小确认条件（仅规则定义，不含效果判断）。

### 适用对象
- 需要过滤“开盘冲高回落”风险的 breakout 候选。

### 优点
- 更贴近“确认后执行”，能减轻部分开盘错位。

### 风险
- 对盘中数据依赖增强；
- 若确认规则过严，可能错过有效样本。

---

## 执行口径 C：T+1 回落不破结构后执行

### 定义
- breakout 信号成立后，不追首冲；
- 等待 T+1 回落测试且结构不破，再进入执行判断。

### 与 pullback 的关系
- 该模式“执行上”接近 pullback；
- 但“信号来源”仍然是 breakout 候选，因此归属于 breakout 执行验证通道是合理的。

### 适用对象
- 对追价风险敏感的 breakout 候选；
- 需要更稳健入场假设的验证场景。

### 风险
- 强势票可能不给回落，导致机会损失；
- 容易把 breakout 通道执行逻辑与 pullback 通道边界混淆。

---

## 三种口径对比结论（仅设计结论）
- 口径 A：最简单，最容易启动验证；
- 口径 B：最能直接解决“继续确认”错位；
- 口径 C：稳健但与 pullback 边界需严格约束。

### 下一阶段优先建议
- **优先细化口径 B（T+1 盘中继续确认）**。  
理由：它最直接针对 T 日确认与 T+1 执行错位，且不需要先把 breakout 与 pullback 混成一条通道。
