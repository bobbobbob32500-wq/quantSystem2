# strong_start 研究版转交易版验证总框架

基线版本：`strong_start_research_v4_freeze1`  
约束：本框架仅做验证设计，不包含回测执行与收益评价。

## 1. 研究版与交易版边界

### 1.1 研究版已完成
- 样本挖掘（事件级）
- 特征快照构建（T日及历史可见）
- A/C 差异分析
- 参数反推与分层（过滤/评分/触发/降级）
- 研究版结构实现与可解释输出
- 小范围多日结构扫描与微调（tune1）
- 冻结收口（freeze1）

### 1.2 研究版未完成
- 买入时点定义与执行口径验证
- 买不到/滑点/高开偏离等执行可达性验证
- 出场规则验证（结构止损、时间止损、动量衰减）
- 持仓与组合层风控规则验证
- 交易事件流闭环验证（signal -> order -> exit）
- 回测与绩效验证

### 1.3 为什么不能直接当交易版
- 研究版回答“像不像真启动”，交易版要回答“何时、如何、能否成交、何时退出”。
- 研究版是事件判别，交易版是执行闭环。
- 研究版在日线收盘可判定，交易版受 T+1 和盘中行为制约。
- 研究版强特征可能是“解释强”，不一定是“可执行买点强”。
- 研究版没有验证止损止盈与持仓风险，直接交易风险不可控。

## 2. 四层交易版验证框架

### 第一层：信号定义验证
目标：
- 将 freeze1 输出稳妥映射为“交易候选信号”。

输入：
- `is_candidate_after_filters`
- `score_total`
- `trigger_status`
- `signal_ready`
- 解释字段（原因链路）

输出：
- 交易候选信号定义规范（信号层级、触发条件、可审计标签）

验收：
- 能对每个事件给出一致的“候选/非候选”与原因。
- 不引入未来字段。

当前是否允许开始：**允许**

### 第二层：执行口径验证
目标：
- 定义交易执行时点与成交假设，防止信号-执行错位。

输入：
- 第一层候选信号
- 日线行情与可选分时数据规范（先设计，不执行）

输出：
- 执行口径规范（T确认、T+1执行、breakout追价边界、pullback确认口径）

验收：
- 每种执行口径均有清晰“可成交/不可成交”判定规则。

当前是否允许开始：设计允许，执行不允许

### 第三层：风控与持仓逻辑验证
目标：
- 定义出场与风险控制框架，避免“只会进不会退”。

输入：
- 信号定义与执行口径规范

输出：
- 止损、止盈、时间退出、结构破坏退出、板块退潮退出草图
- breakout/pullback 分型是否需要分开风控的验证计划

验收：
- 出场逻辑可被事件化表达，不依赖事后口头解释。

当前是否允许开始：设计允许，执行不允许

### 第四层：回测框架验证设计
目标：
- 在真正回测前，先冻结事件流与假设，避免未来函数和时点错位。

输入：
- 前三层规则规范

输出：
- 回测事件流规范文档（输入、状态机、时间对齐、禁止项）

验收：
- 可明确指出所有关键前视风险点与防护机制。

当前是否允许开始：设计允许，回测执行不允许
