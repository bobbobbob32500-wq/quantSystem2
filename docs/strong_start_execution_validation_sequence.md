# strong_start 执行口径验证顺序（设计版）

目标：先冻结执行口径，再进入执行可达性验证，最后才谈回测规范。  
约束：本序列不包含收益评价。

## 阶段 A1：breakout 执行口径细化（优先）
- 目标：
  - 冻结 breakout A/B/C 三种执行口径定义
- 输入：
  - `trade_signal_class=breakout` 候选
  - 执行口径框架文档
- 输出：
  - breakout 执行口径规范（可审计）
- 验收：
  - 每个 breakout 候选都能映射到单一执行口径或拒绝原因
- 当前是否允许开始：**允许**

## 阶段 A2：pullback 执行口径细化
- 目标：
  - 冻结 pullback P1/P2 执行口径
- 输入：
  - `trade_signal_class=pullback_candidate` 候选
- 输出：
  - pullback 执行口径规范
- 验收：
  - pullback 候选都有明确“待验证/拒绝”边界
- 当前是否允许开始：A1通过后允许

## 阶段 B：执行事件表设计
- 目标：
  - 将信号定义表映射为执行假设表
- 输入：
  - A1/A2 口径规范
- 输出：
  - `trade_execution_assumption_table` 设计稿与字段映射
- 验收：
  - 主键唯一、字段完备、拒绝原因可解释
- 当前是否允许开始：A1/A2通过后允许

## 阶段 C：执行可达性验证设计
- 目标：
  - 设计“可达/不可达”验证方法与边界
- 输入：
  - 执行事件表设计稿
- 输出：
  - 可达性验证规范（可选分时扩展计划）
- 验收：
  - 明确日线可验证部分与分时必须验证部分
- 当前是否允许开始：B通过后允许

## 阶段 D：交易版回测规范设计
- 目标：
  - 回测前冻结事件流与防前视约束
- 输入：
  - A/B/C 所有规范
- 输出：
  - 回测事件流规范文档（仅规范，不执行）
- 验收：
  - 关键错位风险有明确防护条款
- 当前是否允许开始：C通过后允许（仍不执行回测）
